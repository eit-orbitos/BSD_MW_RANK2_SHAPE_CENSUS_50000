# Reproducing study V0.2

Run the commands below from the repository root. Use a fresh working copy when
comparing against an existing run: the scientific pipeline writes `results/`,
`tests/` and `logs/`. The retained `recorded_results/` and provenance files are
not overwritten by those commands.

## Environment

The recorded run used **PARI/GP 2.19.1**, **cypari2 2.2.9**, and Python 3.13.18.
It also used mpmath 1.4.1, NumPy 2.5.3 and Matplotlib 3.11.2. These are recorded
versions, not a claim that a new environment has been installed or executed
during repository preparation. The exact environment record is in
`provenance/RECORDED_ENVIRONMENT_V0_2.json`.

Install PARI/GP and its development headers using the upstream instructions,
then build cypari2 against that installation and install the Python dependencies.
Before running, inspect the engine actually loaded by cypari2:

```sh
python3 -c 'from cypari2 import Pari; print(Pari().version())'
```

The exact reproduction target is `[2, 19, 1]`. A wheel can bundle a different
PARI version even when the Python package version matches; record the result of
this check.

## Get and verify the five pinned inputs

With internet access:

```sh
python3 scripts/fetch_inputs.py
```

Or use an existing copy of the unchanged canonical archive:

```sh
python3 scripts/fetch_inputs.py --archive /absolute/path/BSD_MW_SHAPE_STUDY_V0_2.zip
```

The archive option first verifies the full canonical ZIP digest and then reads
only the five exact input members. Both routes verify each input's size and
SHA-256. An existing mismatched input is rejected and left untouched.

```sh
python3 scripts/fetch_inputs.py --verify-only
```

Upstream inputs retain Artistic License 2.0. Their license and attribution
accompany this repository under `third_party/ecdata/`.

## Execute the unchanged scientific pipeline

```sh
sh code/run_all.sh
```

The seven top-level steps and overall run should exit 0, with 23,612 records and
zero unresolved or missing records. The integration suite intentionally injects
failures; it checks that those subprocesses exit 1 while the successful suite
itself exits 0. Inspect `logs/exit_codes.txt`, `results/summary.json` and the
failure ledger before interpreting a run. Expected stored summaries are in
`recorded_results/`; they were copied from the original V0.2 archive.

Use `code/compare_with_v01.py` only with the actual V0.1 package in its first
argument. V0.1 is not included here, and this reproduction command does not
perform a new V0.1–V0.2 comparison. That utility's V0.1 input contract is strict;
do not substitute a V0.2 directory or an incomplete stand-in.

## Manuscript figures

The publication figures can be regenerated from the study CSV after the run:

```sh
python3 code/render_publication_figures.py . figure_output
```

Run this command with a LaTeX installation from `manuscript/` to rebuild the paper:

```sh
pdflatex -interaction=nonstopmode -halt-on-error MW_Rank2_Census_v0_3_4_PREPRINT.tex
pdflatex -interaction=nonstopmode -halt-on-error MW_Rank2_Census_v0_3_4_PREPRINT.tex
```

The current v0.3.4 PDF contains a release-metadata update only. The v0.3.3
PDF/TeX are retained as historical copies, and the figures are unchanged.
Their recorded bytes are independent of any PDF generated by a different TeX setup.

## Interpretation limits

The 45-digit stored fields are numerical results, not interval certificates.
Cross-precision checks and alternative PARI call paths share the same height
engine. The input database supplies the rank and the full-basis assumption.
Agreement in specified scientific fields does not imply byte equality of all
run files, which contain timestamps and runtime diagnostics.

The unchanged V0.2 `analyze.py` contains historical Watkins tail percentages
from the author-hosted version of his paper. The manuscript distinguishes that
version from arXiv v2; the versioned values are documented in
`provenance/WATKINS_VERSIONED_TAILS.csv`. No convergence-to-Haar claim follows
from this finite census.
